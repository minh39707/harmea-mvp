# F2 — MySQL 8.4 và xử lý môi trường Windows

Ngày 11/11/2026. Đã triển khai code và kiểm tra trên **MySQL Community Server 8.4.13 native Windows**, Node 24.15.0. **Còn nghiệm thu Docker và thao tác UI trực tiếp**, chưa đánh dấu F2 hoàn tất toàn bộ tiêu chí.

## Thay đổi

- Thay PostgreSQL/PGlite bằng `mysql2/promise`; gỡ `pg`, `@types/pg`, `@electric-sql/pglite` khỏi dependency và lockfile. Giữ interface adapter, thêm `affectedRows`, pool mặc định 10, UTC và chuyển timestamp thành ISO có `Z`.
- Pool ứng dụng không bật `multipleStatements`. Connection migration riêng mới bật; runner dùng checksum và `GET_LOCK`, chỉ ghi migration sau khi file thành công, báo rõ nguy cơ DDL áp dụng dở.
- Chuyển nguyên nội dung SQL 001–004 cũ sang `database/postgres-legacy/`. MySQL dùng `001_init.sql` và `002_seed_product.sql`; không có `demo_checkouts`, không tự chuyển dữ liệu cũ.
- Schema giữ ràng buộc/index nghiệp vụ, InnoDB/utf8mb4, JSON object, hash, trạng thái, version, số lượng và giá. Bỏ ba cột không còn được API đọc ở `orders`: `design_snapshot`, `photo_key`, `preview_key`; dữ liệu thiết kế/ảnh nằm trong `order_items`.
- Đổi placeholder sang `?`, bỏ `RETURNING`, chọn lại đơn theo UUID, bắt `ER_DUP_ENTRY` cho requestKey và kiểm tra version bằng `affectedRows`. Alias `isDemoPrice` tiếp tục trả boolean.
- Sửa sai số crop do parser JSON của MySQL: ghi các tọa độ qua `JSON_SET`/`CAST(? AS DOUBLE)`. Giữ các assertion so sánh chính xác; bổ sung giá trị rất nhỏ và tiếng Việt/emoji.
- Test helper tạo/migrate/drop DB `harmea_test_<random>`, có hook cleanup khi test fail; thiếu `TEST_DATABASE_URL` báo lỗi rõ. Trigger gây lỗi thật được chuyển sang cú pháp MySQL. Bài backfill PostgreSQL 004 được thay bằng bài kiểm tra schema MySQL canonical vì F2 không nhập DB PostgreSQL cũ.
- Compose dùng `mysql:8.4`, cổng chỉ bind loopback, volume `harmea_mysql`, healthcheck. `MYSQL_PORT` mặc định 3306 cho phép tránh dịch vụ đã chiếm cổng.
- `setup` sinh mật khẩu MySQL riêng cho app/root và giữ file `.env` đã có. Sửa lỗi CRLF trên Windows làm bỏ sót hash admin; thêm test sinh thông tin khớp nhau, không in bí mật và không ghi đè file đã có.

Qua HTTP/Vite proxy đã tạo đơn hư cấu, đăng nhập bằng admin local, đọc chi tiết và ảnh riêng tư, tra tracking bằng POST body; kiểm tra trực tiếp đơn có trong MySQL. Sau khi dừng và chạy lại chính tiến trình API kiểm tra, cùng đơn/ảnh/tracking vẫn đọc được. Đây là kiểm tra HTTP và tiến trình thật, **chưa phải thao tác UI qua trình duyệt**.

Đơn thử không dùng để sản xuất/giao hàng. Receipt/token chỉ lưu trong `storage/private/f2-live-receipt.json`, không in log hoặc đưa vào báo cáo. Server cũ ở 4000/5173 được giữ; cơ chế xét duyệt đã chặn thao tác dừng server cũ, nên dùng instance riêng để kiểm tra.

## Môi trường local đã sửa

- Docker Desktop không khởi động engine vì thiếu WSL. Không cài tính năng Windows hoặc khởi động lại máy trong phiên này.
- Dùng ZIP MySQL chính thức, không cài Windows service mới: [MySQL Community Server 8.4 cho Windows](https://dev.mysql.com/downloads/mysql/8.4.html?os=3). ZIP 8.4.13 có MD5 `7b94489d5524dea9b27097068bea25a8`, đã đối chiếu trước khi dùng.
- Instance làm việc được đặt tại `%LOCALAPPDATA%\Harmea\mysql84`, chỉ bind `127.0.0.1:33384`. MySQL 8.0 sẵn có ở cổng 3306 không bị thay đổi.
- Đã nâng cấu hình DB trong `.env` local, sinh mật khẩu app/root riêng; bản cũ sao lưu tại `storage/private/f2-env-before-mysql-2026-11-11.env`. Hash admin bị trống đã được sửa từ mật khẩu local hiện có, không đổi mật khẩu trong `.local-admin.txt`.
- Nếu instance native chưa chạy sau khi mở lại máy, từ thư mục dự án dùng:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\storage\start-mysql84.ps1
npm.cmd run db:check
npm.cmd run dev
```

Launcher trong `storage/` chỉ dành cho máy hiện tại và bị Git bỏ qua; không thuộc gói bàn giao. Server cũ chiếm 4000/5173 cần được đóng trước khi chạy `npm run dev` bình thường. Instance kiểm tra hiện tại truy cập tại `http://127.0.0.1:5174`.

MySQL Windows báo `CreateProcess Failed (267)` nếu khởi động từ đường dẫn làm việc có dấu của dự án. Launcher đã dùng thư mục làm việc ASCII trong LocalAppData. Các instance MySQL thử ở cổng 33306 và bản tạm 33384 đã dừng; bản đang dùng là instance riêng ở LocalAppData.

## Giới hạn và việc còn lại

- Bật/cài WSL2 và khởi động Docker engine để chạy lại Compose; Compose chưa được nghiệm thu runtime. Khi chuyển native sang Docker, cần dừng native để giải phóng cổng; hai kho DB không tự chuyển dữ liệu.
- Kiểm tra đặt hàng/admin/tracking bằng thao tác trình duyệt, IndexedDB/Canvas/clipboard và responsive. Phiên này không có browser/Computer Use runtime khả dụng.
- Chưa kiểm tra production, tải lớn, power loss, phần cứng NFC hoặc file in.
- Tự động xét duyệt chặn thao tác xóa các thư mục MySQL thử trong Temp, chỉ trả lý do `blocked by policy`. Vì vậy ba thư mục dưới đây còn trên máy; không còn server thử sử dụng chúng:
  - `%TEMP%\harmea-f2-mysql80-9dd5741ae3b64674a3dea7c9772c511b`
  - `%TEMP%\harmea-f2-test-mysql80-d0f07e499a6e471abc2c15ffe5db6339`
  - `%TEMP%\harmea-f2-runtime-84`

Thay đổi để trong working tree theo prompt task hiện hành; không commit/push. Các chỉnh sửa giao diện và các task khác đang có trong workspace không được tính là phần triển khai F2.
