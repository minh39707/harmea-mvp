## Vì sao smoke legacy còn 5 mismatch

1. Duplicate request trên route demo vẫn replay 200; canonical `/api/orders` đã trả 409 và token một lần.
2. Probe `/api/orders` gửi JSON rỗng nhận 415 thay vì 422 cũ; 415 đúng vì endpoint mới yêu cầu multipart.
3. Token lấy từ kho demo không tìm thấy ở canonical lookup, nhận 404; không tự nhập chung hai kho.
4. `/admin/login` còn 404 vì UI thuộc task D.
5. Snapshot demo không có preview PNG; API canonical đã lưu và tải đúng PNG, editor/client phải nối ở B/C.

Không sửa bằng chứng QA/E1 lịch sử hoặc đổi kỳ vọng smoke để che mismatch. QA-01/02/03/05 đã có phần backend canonical; phần UI/legacy còn rõ như trên. QA-04 response đã khớp contract cập nhật; QA-06/07 thuộc B/C.

## Giới hạn và vận hành

- Chưa thử PostgreSQL/Docker server hoặc tải public; race/version đã kiểm tra PGlite, chưa coi là nghiệm thu nhiều process/PostgreSQL.
- Chưa kiểm tra trình duyệt, UI admin, preview render/crop của editor, clipboard/responsive hoặc NFC vật lý. Chưa đánh dấu checklist UI docs/04 là PASS.
- Parser multipart có buffer giới hạn 16 MiB và hai request đồng thời/process; không phải streaming-to-disk. Chưa đo peak RSS hoặc tải dài. Tổng giới hạn có thể buộc giảm dung lượng ảnh dù từng file còn trong 5/2 MiB.
- Filesystem và DB không atomic trước process crash/power loss; nhánh lỗi thông thường đã dọn file, chưa có job dọn orphan sau crash. Thư mục test tạm giữ trên máy, không commit/ZIP.
- **Database local đang chạy chưa được migrate/restart.** Dừng API trước khi chạy `npm.cmd run db:migrate`, `npm.cmd run db:check`, rồi khởi động lại. Không mở hai process cùng PGlite DATA_DIR. Các tests chỉ dùng DB tạm riêng, giữ nguyên đơn và admin hiện có.
- `APP_ORIGIN` HTTPS bật Secure cookie; demo HTTP loopback không bật. Chưa thiết kế vận hành reverse proxy/cloud.
