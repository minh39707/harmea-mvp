## Những vấn đề đã tái hiện qua API

### QA-01 — Cao: API đặt đơn và tracking không theo hợp đồng

**Bước tái hiện:** Tạo đơn qua `POST /api/demo-checkouts` theo payload trong `scripts/qa-smoke.mjs`; dùng token trả về gọi `POST /api/tracking/lookup`. Gọi thêm `POST /api/orders` với JSON rỗng để xác định route hiện hữu.

**Thực tế:** Route demo tạo được đơn (201), `/api/demo-tracking` đọc được đơn (200), nhưng đường dẫn lookup trong hợp đồng trả 404 ngay cả với token hợp lệ. `/api/orders` trả 404 thay vì đi vào xử lý tạo đơn. Frontend hiện chỉ nối với các route demo.

**Kỳ vọng:** Luồng tạo đơn multipart/lookup thực hiện theo `contracts/openapi.json`, hoặc có quyết định đổi phạm vi được đồng bộ thành hợp đồng mới. Không thể dùng contract hiện tại để tích hợp client này.

**Vị trí:** `apps/api/src/commerce.ts:22,63`, `apps/web/src/App.tsx:39,40`; đối chiếu task A/C. Đây là khoảng trống tích hợp so với P0, không phải bằng chứng luồng demo hiện tại hoàn toàn hỏng.

### QA-02 — Cao: Chưa có admin để xử lý các đơn đã lưu

**Bước tái hiện:** Gọi `POST /api/admin/session` với `{}`, `GET /api/admin/orders` khi chưa đăng nhập và mở `/admin/login` trực tiếp qua Express.

**Thực tế:** Cả ba trả 404; không có chức năng đăng nhập, xem đơn/ảnh hoặc đổi trạng thái trong router hiện tại. `demo_checkouts.status` bị ràng buộc chỉ nhận `pending` trong migration 003.

**Kỳ vọng:** Có phiên admin, danh sách/chi tiết, ảnh riêng tư, trạng thái và lịch sử đúng task A/D; gọi danh sách thiếu phiên trả 401. Cần bổ sung migration mới nếu thay schema đã áp dụng.

**Ảnh hưởng:** Không hoàn tất được vòng khách đặt → admin xử lý → khách thấy tiến độ. Đây là chức năng P0 còn thiếu; chưa có bằng chứng lộ dữ liệu do thiếu auth vì route chưa tồn tại. UI có công khai giới hạn không sản xuất/giao hàng của bản demo.

### QA-03 — Cao: Không lưu được bản preview PNG và ảnh gốc theo đầu ra designer

**Bước tái hiện:** Chạy phép thử `real PNG accepted`, rồi xem cách `photo()` tạo payload và snapshot mà checkout lưu.

**Thực tế:** PNG đầu vào được đổi thành JPEG đã resize; frontend cũng nén ảnh về tối đa 600 px trước khi gửi. Snapshot giữ dữ liệu thiết kế nhưng không có preview PNG, ảnh gốc, cấu hình crop. Không có đường lấy preview riêng tư cho admin.

**Kỳ vọng:** Giữ ảnh gốc và preview PNG đúng thiết kế đã xác nhận, có cấu hình crop/template để đối chiếu (task B/A). Hiện không thể khôi phục ảnh gốc hoặc chứng minh đúng bản thiết kế khách đã xem từ dữ liệu lưu.

**Vị trí:** `apps/web/src/App.tsx:36,39`, `apps/api/src/commerce.ts:35–43,53`, `database/003_demo_cart_checkout.sql`.

### QA-04 — Vừa: Response sản phẩm sai schema OpenAPI

**Bước tái hiện:** `GET /api/products/current`, so sánh với `components.schemas.Product`.

**Thực tế:** Thiếu 4 trường bắt buộc `isDemo`, `physicalSizeMm`, `artworkSizeMm`, `safeAreaMm`; thêm `isDemoPrice`, `image`, `cardSizeMm` dù schema cấm additionalProperties.

**Kỳ vọng:** Response đúng schema, frontend dùng cùng tên trường. Các kích thước artwork/safe area cần được thể hiện đúng trong logic template.

**Vị trí:** `apps/api/src/commerce.ts:20`. Frontend hiện dùng schema riêng nên vẫn tải giá được; lỗi ảnh hưởng client tuân theo hợp đồng và nghiệm thu mẫu.

### QA-05 — Vừa: Gửi trùng trả lại tracking token, trái quy tắc P0

**Bước tái hiện:** Gửi cùng payload và `requestKey` hai lần vào `/api/demo-checkouts`.

**Thực tế:** Lần đầu 201, lần sau 200, cùng mã đơn và lại trả `trackingToken`. Gửi cùng khóa nhưng đổi nội dung trả 409 đúng; gửi đồng thời không tạo thêm dòng.

**Kỳ vọng theo task A/C và docs/02:** Lần trùng trả 409, token chỉ trả một lần, giao diện hướng dẫn xử lý khi mất response. Code hiện dùng HMAC tái tạo token thay vì token ngẫu nhiên chỉ trả lần đầu.

**Vị trí:** `apps/api/src/commerce.ts:14,48,56`. Nếu replay response là chủ đích mới cho demo, cần quyết định và cập nhật hợp đồng/tài liệu trước khi coi là đạt; không ghi nhận đây là lỗi tạo trùng đơn.

## Vấn đề xác định qua code — cần Minh tái hiện trên trình duyệt

### QA-06 — Vừa: Ngày sinh nhập vào không xuất hiện trên preview

**Cách thử:** Mở cá nhân hóa → mở phần thêm ảnh/chữ ký/ngày → nhập hai ngày sinh khác nhau và quan sát preview.

**Bằng chứng code:** Input cập nhật `design.dateOfBirth`, backend lưu trường này, nhưng `Card()` không render nó (`apps/web/src/App.tsx:18,51`). Task B yêu cầu mẫu có ngày sinh và preview thay đổi theo thông tin nhập.

**Cần sửa:** Render ngày sinh đúng template hoặc làm rõ trường này không phải nội dung in. Chưa xác nhận trực quan do công cụ trình duyệt không kết nối được.

### QA-07 — Vừa: Đặt lần mới giống hệt lần trước có thể bị nhận thành replay

**Cách thử:** Đặt thành công → bấm trở lại bộ sưu tập → tạo lại thiết kế/số lượng/người nhận giống hệt → xác nhận đặt thử lần nữa, không reload trang.

**Bằng chứng code:** `signature.current` và `requestKey.current` không reset sau thành công; lần sau cùng nội dung sẽ dùng lại khóa (`apps/web/src/App.tsx:39`). API replay khóa cũ đã xác nhận ở QA-05, nên có thể trả mã đơn cũ thay vì tạo đơn mới.

**Cần sửa:** Sinh khóa mới khi bắt đầu lần đặt mới sau thành công, chỉ giữ khóa cho retry của lần chưa rõ kết quả. Phần UI chưa chạy trực tiếp; kết luận hiện dựa vào code kết hợp hành vi API.

### QA-08 — Thấp: README và tài liệu trạng thái chưa phản ánh bản demo hiện tại

**Cách kiểm tra:** Đọc phần “Đã có / cần làm tiếp” và hướng dẫn địa chỉ trong README, so với các API demo đã chạy phía trên.

**Thực tế:** README còn ghi web trống, chỉ health có sẵn; OpenAPI không mô tả route demo; migration 003 lại ghi scope nhiều thiết kế/giỏ hàng. AGENTS và docs/01–05 vẫn quy định một thiết kế/không giỏ hàng.

**Cần sửa:** Ghi riêng trạng thái demo đã làm, phần P0 chưa làm, và quyết định phạm vi chính thức. Không đánh dấu endpoint kế hoạch đã triển khai. Báo cáo này không tự phê duyệt việc mở rộng scope.

## Cách Minh chạy lại

```powershell
npm.cmd run typecheck
npm.cmd run build
npm.cmd run contract:check
npm.cmd run test:smoke
```

Script tạo database thử mới trong thư mục tạm hệ điều hành, không nạp `.env`, không dùng `storage/db` và không dừng server người dùng. Chạy sau build để phép thử route trang dùng đúng bundle. Kết quả ghi vào `docs/qa-evidence-2026-10-29.json`; chỉ chứa tên phép thử, HTTP status/kết quả tổng hợp, không chứa bí mật. Script luôn in tổng hợp và thoát bình thường kể cả có mismatch để phục vụ khảo sát; đọc trường `pass` và tổng số, không coi exit code 0 là nghiệm thu thành công.

## Giới hạn kiểm tra

Chưa thao tác giao diện, kiểm tra responsive 390 px, clipboard, upload ảnh ngang/dọc trực quan, Back/refresh hoặc render font. Browser access host và Windows native pipe đều không khả dụng trong phiên này; không có ảnh chụp bằng chứng UI. Chưa thử PostgreSQL/Docker, phần cứng NFC, tải lớn/rate limit, rollback bằng lỗi insert event hoặc state machine/auth/concurrency version của đơn P0 vì các chức năng đó chưa triển khai. Phép restart là đóng/mở server và PGlite thử, không phải reboot máy hay dừng tiến trình app đang chạy.

Ưu tiên xử lý: thống nhất scope/hợp đồng → admin và vòng xử lý đơn → lưu ảnh gốc/preview → khóa yêu cầu cho lần đặt mới → ngày sinh trên preview → cập nhật hướng dẫn. QA-06/07 cần được xác nhận lại bằng trình duyệt trước khi đóng lỗi.
